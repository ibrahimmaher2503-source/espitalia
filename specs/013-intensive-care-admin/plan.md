# Implementation Plan: Intensive Care Admin Platform

**Branch**: `013-intensive-care-admin` | **Date**: 2026-04-05 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/013-intensive-care-admin/spec.md`

## Summary

Extend the existing IntensiveCare module with full bilingual (AR/EN) support for all entity text fields, complete admin CRUD backend (hospitals, departments, admission requests), location integration (governorate/city), platform commission and earnings system, and REST API endpoints. All patterns mirror established conventions from the Nurse bilingual (012), Location, and Pharmacy commission (011) modules.

## Technical Context

**Language/Version**: PHP 8.2+ / Laravel 11.x
**Primary Dependencies**: nwidart/laravel-modules 10.x, spatie/laravel-permission, Laravel Sanctum, DataTables, Select2, jQuery, Blade
**Storage**: MySQL/MariaDB (SQLite in-memory for tests)
**Testing**: PHPUnit with SQLite in-memory
**Target Platform**: Web (admin panel) + REST API (mobile/third-party)
**Project Type**: Web service — modular SaaS application
**Performance Goals**: Earnings dashboard loads in <2s for 10k records; admin CRUD pages standard web latency
**Constraints**: Bilingual AR/EN on all text fields; role-based access (admin, demo_admin, hospital_coordinator)
**Scale/Scope**: ~7 migrations, 6 models (3 updated + 3 new), 5 admin controllers, 2 API controllers, 6 Blade view sets, 2 translation files, 1 service class, ~15 admin pages total

| Principle | Status | Evidence |

| I. Module Encapsulation | PASS | All code resides in `Modules/IntensiveCare/`. Commission entities (IcuCommission, IcuCommissionEarning, IcuPayout) live in the module, not shared. Cross-module references (Location) use Eloquent BelongsTo relationships only. |

Views extend `backend.layouts.app`. |
| III. Role-Based Access Control | PASS | 6 new permissions declared via seeder. Web routes gated by middleware permission checks. API endpoints validate authorization. Sidebar entries conditionally rendered by role. Hospital coordinators scoped to own hospital data. |
| IV. Test Discipline | PASS | Unit tests planned for all 3 new models (IcuCommission, IcuCommissionEarning, IcuPayout), updated tests for bilingual accessors on 3 existing models, commission service test, permission seeder test. |
| V. Simplicity and YAGNI | PASS | Replicates proven patterns (Pharmacy commission, Nurse bilingual) without new abstractions. No new dependencies. Uses existing DataTables, Select2, Blade components. Commission service is a single-purpose class. |
